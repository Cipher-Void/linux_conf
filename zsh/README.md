# Dotfiles — zsh конфиг

Личный конфиг zsh (`~/.config`), заточенный под работу на нескольких машинах
(WSL + Arch Linux) с одной кодовой базой, без дублирования настроек.

## Идея

1. **`~/.config` — это сам репозиторий.** После переустановки системы весь
   конфиг приезжает одним `git clone`, `install.sh` только доустанавливает
   зависимости (zsh, oh-my-zsh, плагины) и раскладывает пару файлов в `$HOME`.
2. **Конфиг разбит на модули**, а не лежит одним файлом — так проще найти,
   что где лежит, и не бояться что-то сломать при правке.
3. **Один код работает на разных машинах.** Переменная `DOTFILES_PROFILE`
   определяет, на какой системе мы сейчас (`wsl` / `arch`), и грузит только
   нужные под неё файлы. Профиль детектится автоматически, но можно
   переопределить руками.
4. **Есть два момента загрузки — до и после oh-my-zsh.** Некоторые настройки
   (переменные для плагинов вида `ZVM_*`) обязаны быть заданы **до**
   `source oh-my-zsh.sh`, а некоторые (алиасы, которые должны перебить
   встроенные алиасы oh-my-zsh) — **после**. Это два разных этапа, а не один
   список файлов.

## Структура

```
~/.zshenv                          # единственный файл в $HOME, копия шаблона

~/.config/
    zsh/
        .zshenv.template            # шаблон, из которого копируется ~/.zshenv
        .zshrc                      # главный загрузчик, сам по себе логики не содержит
        rc.d/
            00-detect-profile.zsh   # определяет $DOTFILES_PROFILE
            30-oh-my-zsh.zsh        # настройка темы/плагинов, source oh-my-zsh.sh
            pre/                    # грузится ДО oh-my-zsh
                common/             # общее для всех систем
                wsl/                # только для WSL
                arch/               # только для Arch
            post/                   # грузится ПОСЛЕ oh-my-zsh
                common/
                wsl/
                arch/
    shared/
        detect-profile.sh          # логика детекта профиля (используется не только zsh)
    shims/
        wsl/                        # обёртки над Windows-бинарниками (см. ниже)
install.sh                          # разворачивает конфиг после переустановки системы
```

## `DOTFILES_PROFILE`

Переменная окружения, показывающая, на какой системе сейчас работаем:
`wsl`, `arch`, либо `generic`, если не распознано.

- Определяется один раз в `~/.config/shared/detect-profile.sh`.
- Используется не только в zsh — та же переменная задействуется в tmux и
  Nvim, чтобы не дублировать логику детекта в трёх местах.
- Можно переопределить руками, если нужно временно подменить профиль:
  ```bash
  DOTFILES_PROFILE=arch zsh
  ```
- Автодетект не перезатирает уже заданное значение — если переменная
  экспортирована заранее, детект её не трогает.
## Почему pre/ и post/
Плагины oh-my-zsh читают некоторые переменные окружения 
**в момент своей инициализации** (например, `zsh-vi-mode` смотрит на `ZVM_CLIPBOARD_*`). Если
такая переменная задана после `source oh-my-zsh.sh` — плагин её просто не
увидит.

С другой стороны, у самого oh-my-zsh есть встроенные алиасы (например,
`alias ls='ls --color=tty'` в теме), которые перетирают всё, что было
объявлено раньше. Чтобы твой `alias ls=lsd` реально сработал, он должен
грузиться **после** oh-my-zsh, а не до.

Поэтому:

| Этап   | Что туда кладём                                             |
|--------|---------------------------------------------------------------|
| `pre/`  | переменные окружения, нужные плагинам до их инициализации (`ZVM_*`, `PATH`, секреты) |
| `post/` | алиасы, функции — всё, что должно перебивать дефолты oh-my-zsh |

Файлы внутри `pre/` и `post/` разложены по `common/` (везде) и
профилям (`wsl/`, `arch/`) — грузится общее, затем то, что относится
к текущему `$DOTFILES_PROFILE`.

## `.zshrc` — порядок загрузки

```
00-detect-profile.zsh
  → pre/common/*.zsh
  → pre/$DOTFILES_PROFILE/*.zsh
  → 30-oh-my-zsh.zsh
  → post/common/*.zsh
  → post/$DOTFILES_PROFILE/*.zsh
```

Файлы внутри каждой папки грузятся в алфавитном порядке — числовой префикс
(`00-`, `10-`, `40-`...) задаёт порядок внутри одного этапа, если он важен.
Между собой имена файлов в `pre/` и `post/` не обязаны совпадать, но по
смыслу совпадают: `10-env.zsh` — переменные, `40-aliases.zsh` — алиасы,
`50-nvm.zsh` — то, что грузится лениво/отдельно.

## Секреты

`pre/common/00-secrets.zsh` — API-ключи и прочие чувствительные значения.
Файл в `.gitignore`, в репозитории не хранится. Если конфиг клонируется на
новую систему — секреты нужно создать вручную.

## Shims — обёртки над Windows-бинарниками

Некоторые программы (Docker Desktop, Obsidian и т.п.) установлены только в
Windows, а вызываются из WSL. Два способа их подключить:

- **Консольные утилиты, которые проверяются другими плагинами при старте
  shell** (например, `docker` — плагин `docker` в oh-my-zsh делает
  `command -v docker` при инициализации) — нужен **реальный исполняемый
  файл** в `$PATH`, алиас или функция здесь не сработают, потому что
  `$commands`/`command -v` не видит ни то, ни другое.

  Такие обёртки лежат в `~/.config/shims/wsl/` и копируются в
  `~/.local/bin/` через `install.sh` (по желанию, не автоматически):
  ```bash
  #!/usr/bin/env bash
  exec "/mnt/c/Program Files/Docker/Docker/resources/bin/docker.exe" "$@"
  ```

- **GUI-приложения и всё, что не проверяется другими скриптами при старте**
  (Obsidian, `explorer.exe`) — достаточно обычного алиаса в
  `post/wsl/40-aliases.zsh`:
  ```bash
  alias obsidian="/mnt/c/Users/<user>/AppData/Local/Obsidian/Obsidian.exe"
  alias open="/mnt/c/Windows/explorer.exe"
  ```

## `install.sh`

Разворачивает конфиг на новой системе. Не создаёт структуру каталогов
(она уже приезжает с `git clone ~/.config`), а только:

1. Ставит `zsh`, `git`, `curl`, если их нет (через `pacman`/`apt`).
2. Копирует `zsh/.zshenv.template` → `~/.zshenv`, с бэкапом старого файла.
3. Ставит `oh-my-zsh` в `$XDG_DATA_HOME/oh-my-zsh` (не в `~/.oh-my-zsh`).
4. Клонирует плагины, которых нет в стандартном oh-my-zsh
   (`zsh-vi-mode`, `zsh-syntax-highlighting`).
5. По желанию — копирует shims для текущего профиля в `~/.local/bin`.
6. По желанию — меняет дефолтный shell на zsh.

Идемпотентен — повторный запуск не ломает уже настроенную систему,
пропускает шаги, которые уже выполнены.

### Запуск на новой системе

```bash
git clone <адрес-репозитория> ~/.config
cd ~/.config
bash install.sh
exec zsh
```

## XDG-переменные

Конфиг старается не плодить файлы в `$HOME` и использует стандартные
XDG-каталоги:

| Переменная | Значение по умолчанию | Что там лежит |
|---|---|---|
| `ZDOTDIR` | `~/.config/zsh` | сам zsh-конфиг |
| `XDG_CONFIG_HOME` | `~/.config` | конфиги |
| `XDG_DATA_HOME` | `~/.local/share` | oh-my-zsh и его плагины |
| `XDG_CACHE_HOME` | `~/.cache` | кэш completion'ов oh-my-zsh |

Все они задаются один раз в `~/.zshenv` — единственном файле, который
физически живёт в `$HOME`, а не в репозитории.

## Добавление нового плагина

Если плагин не входит в стандартный oh-my-zsh (как `zsh-vi-mode` и
`zsh-syntax-highlighting`):

1. Добавить клонирование в `install.sh`, по аналогии с уже существующими.
2. Прописать имя в `plugins=(...)` в `rc.d/30-oh-my-zsh.zsh`.
3. Если плагин при инициализации проверяет наличие внешней команды —
   оборачивать подключение в `command -v <тул> >/dev/null 2>&1 && plugins+=(...)`,
   чтобы плагин не падал с `command not found` на системах, где этой
   команды нет.
4. `zsh-syntax-highlighting` должен идти **последним** в списке
   `plugins=(...)` — это требование самого плагина.

## Добавление нового профиля-специфичного файла

- Переменная окружения, нужная плагину до его загрузки → `pre/<profile>/`.
- Алиас или функция, которая должна перебить дефолт oh-my-zsh → `post/<profile>/`.
- Что-то общее для всех систем → `pre/common/` или `post/common/`
  соответственно.
